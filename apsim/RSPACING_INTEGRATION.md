# rSpacing integration contract

`Spacing.Tool2` is the machine-facing entry point for one calibration iteration or one agronomic scenario.

## Invocation

```text
dotnet run --project src/Spacing.Tool2 -- --config spacing.config.json --request request.json --mock --result output/result.json
```

The separator `--` before tool arguments is mandatory with `dotnet run`. Diagnostics use stderr. The only stdout payload is JSON.

## Request fields

- `run_id`: stable identifier generated by rSpacing.
- `metadata`: arbitrary string/JSON values, e.g. chain, iteration, treatment.
- `mock`, `calibrate`, `start_year`, `end_year`, `lat`, `lon`, `cell_id`.
- `weather_file`: existing APSIM `.met` file; when omitted the configured API/mock supplies weather.
- `soil_profile`: optional complete `SoilProfile`, including `layers`; when omitted the configured API/mock supplies soil.
- `crops`: ordered crop rotation. Each crop may include `management` and numeric `parameter_overrides`.
- `observations_file`, `calibration_parameters_file`, `result_file`, `manifest_file`.

CLI values take precedence over request fields. Fixed `parameter_overrides` are merged with calibrated values; calibrated values win for the same key.

## Reproducibility

Every run writes a JSON manifest containing run id, engine, metadata, coordinates, soil id/source, weather path, years, full rotation, fixed overrides, outputs and errors.

## Batch integration with Spacing.Tool1

rSpacing can provide a JSON array of `CropRotation` objects, or an object with a `scenarios` array:

```text
dotnet run --project src/Spacing.Tool1 -- --config spacing.config.json --mock --scenarios scenarios.json --result output/batch.json
```

Each scenario can carry per-crop `ParameterOverrides`, so the same fixed APSIM parameter contract is used by the core builder, Tool1 and Tool2.
